# Plan 06-02: Dashboard Status Views Integration & Consolidation

## Objective
Refactor all status list views (`DraftDocs.js`, `CompleteDocs.js`, `DeclinedDocs.js`, `RecallDocuments.js`, `InActive.js`, and `PendingDocs.js`) to consume the centralized `<DocumentStatusTable />` engine and `statusTableConfig.js`, eliminating duplicate table wrappers, manual pagination math, and inconsistent status badge styles while strictly preserving all existing API endpoints, modals, and user permissions.

## Context
With `<DocumentStatusTable />` and `statusTableConfig.js` implemented in Plan 06-01:
- Each status view currently maintains its own TableContainer, Table, TableHead, TableBody, empty state block, and pagination elements (~100-150 LOC duplicated per view).
- Modals (view, download, transfer ownership, change sign order, resend notification, recall, inactive) remain unique to each view's business logic and will be plugged cleanly into row actions or custom toolbar actions.
- Permissions (`userAccess.remainingDays <= 0`) and account roles must be preserved exactly as implemented.

## Execution Details
1. **Refactor `DraftDocs.js`**:
   - Utilize `<DocumentStatusTable />` with draft column configuration, toolbar filter, and draft row actions (Inactive, Edit, View).
2. **Refactor `CompleteDocs.js`**:
   - Utilize `<DocumentStatusTable />` with completed column configuration, completed date, status badge, and actions (Download, View, Share, SignOrder, Certificate, Supporting Docs).
3. **Refactor `DeclinedDocs.js`**:
   - Utilize `<DocumentStatusTable />` with declined columns, reason cell, and actions (Download, View, SignOrder).
4. **Refactor `RecallDocuments.js`**:
   - Utilize `<DocumentStatusTable />` with recalled columns, reason cell, and actions (Download, View, SignOrder).
5. **Refactor `InActive.js`**:
   - Utilize `<DocumentStatusTable />` with inactive columns and actions (Activate, View).
6. **Harmonize `PendingDocs.js`**:
   - Standardize table headers, column widths, and pagination using `statusTableConfig.js`.
7. **Update UI Module Inventory Tracker**:
   - Document the unified table engine across dashboard statuses in `UI_MODULE_INVENTORY.md`.

## Verification
- Run full test suite: `node --test src/**/*.test.js`.
- Run production build: `npm run build`.
- Verify zero box-shadows and `--modern-*` token usage across all status screens.
