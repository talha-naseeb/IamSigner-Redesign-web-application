# Plan 07-01: Universal Multi-Format DMS File Upload Engine with Real-Time Progress & Metadata Tagging

## Objective
Implement universal multi-format file upload support in the DMS upload modal with client-side validation up to 100MB, real-time progress bar tracking, multi-file selection management (with size indicators and removal buttons), rich metadata tagging (title, description, tags, and optional notification date reminders), and token-based button loading states adhering strictly to design guidelines.

## Context
Requirement `DMS-01` specifies:
"Multi-format DMS file upload modal supports any file type up to 100MB with progress tracking and metadata tagging."
Currently:
1. `src/Components/DMS/constants/dmsConfig.js` sets `DMS_MAX_UPLOAD_BYTES` to 50MB (`50 * 1024 * 1024`). It must be updated to 100MB (`100 * 1024 * 1024` = 104,857,600 bytes).
2. `UploadModal.js` maintains an `uploadProgress` state and passes an `onProgress` callback to `onUpload`, but the progress percentage is never rendered to the user.
3. `UploadModal.js` lists selected files as plain text without file size indicators or ability to remove an individual file.
4. `UploadModal.js` lacks an active progress bar with percentage during file transfers.
5. Translations in `en` and `ar` reference a 50MB limit and specific extensions rather than universal multi-format up to 100MB.

## Tasks
1. **DMS Upload Configuration (`src/Components/DMS/constants/dmsConfig.js`)**:
   - Update `DMS_MAX_UPLOAD_BYTES` to `100 * 1024 * 1024` (100MB).
   - Add `formatFileSize(bytes)` utility for human-readable file sizes (e.g., `520 B`, `14.2 KB`, `45.8 MB`).
   - Add `validateDmsFiles(files, maxBytes)` utility returning `{ isValid, error, oversizedFiles, validFiles }`.
   - Expand `FILE_TYPE_CONFIG` and `getDmsFileTypeIcon(ext)` to support all common extensions (TXT, RTF, ZIP, RAR, 7Z, CSV, PNG, JPG, JPEG, GIF, WEBP, SVG, PPT, PPTX, XLS, XLSX, DOC, DOCX, PDF, MP4, MP3, JSON, XML) and clean fallback for any binary format.
2. **Upload Modal Enhancements (`src/Components/DMS/modals/UploadModal.js`)**:
   - Enable universal multi-format file selection (no restrictive `accept` constraints).
   - Display selected files with file type icons, name, human-readable size, and an individual remove button (`×`).
   - Render a dedicated real-time progress bar container when `isUploading` is active showing current upload percentage (`0% - 100%`) with smooth transitions.
   - Disable input fields and controls while `isUploading` is true.
   - Show a compact spinner inside the submit button while preserving the button label and displaying progress percentage: e.g., `<Spinner size="sm" /> {uploadProgress > 0 ? \`${t("DMS.uploading")} (\${uploadProgress}%)\` : t("DMS.uploading")}`.
   - Ensure metadata tagging fields (title, description, tags via `TagsInput`, optional notification reminder date & days before) remain intact and clean.
3. **CSS Styling Updates (`src/Components/DMS/dms.css`)**:
   - Style `.dms-upload-progress-container`, `.dms-upload-progress-bar`, and `.dms-selected-file-chip` using `--modern-*` design tokens with zero decorative box-shadows.
4. **Localization Updates (`src/Components/Translation/en/translation.json` & `ar/translation.json`)**:
   - Update `uploadHint` and `fileTooLarge` to reflect universal multi-format support up to 100MB.
   - Ensure keys for `uploading`, `removeFile`, and `fileSize` exist.
5. **Unit Test Suite (`src/Components/DMS/constants/dmsUploadConfig.test.js`)**:
   - Write tests for `DMS_MAX_UPLOAD_BYTES` constant.
   - Write tests for `formatFileSize` formatting across B, KB, and MB ranges.
   - Write tests for `validateDmsFiles` testing valid files, oversized files (>100MB), and empty inputs.
   - Write tests for `getDmsFileTypeIcon` and `getFileConfig` with universal extensions.
