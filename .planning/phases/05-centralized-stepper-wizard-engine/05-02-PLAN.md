# Plan 05-02: Step 1 (Document Source & Upload Engine) Shared Extraction & Consolidation

## Objective
Extract repetitive, duplicated Step 1 upload UI and source cards (Dropzone, Google Drive, OneDrive, Dropbox, and DMS) and the uploaded document table into reusable components under `src/Components/DocumentPreparation/Step1_Source/`, then integrate them into the 4 FirstStep components (`Upload Flow`, `BulkSend`, `SelfSignature`, and `Templates`) to reduce code duplication by >40% while preserving all document upload functionality.

## Context
Step 1 across all four flows handles:
1. **Source Pickers**: Drag & Drop dropzone, Google Drive (`UploadFromGoogleDrive`), OneDrive (`OneDriveIntegration`), Dropbox (`Dropbox`), and DMS modal picker (`DmsDocumentPickerModal`).
2. **Document Metadata**: Reference Number (`ReferenceNumber.js`) and Description (`Description.js`) — already present in `DocumentPreparation/Step1_Source/`.
3. **Uploaded Document Table**: Showing file name, size, page count, and action buttons (delete, preview, template application).
4. Each of the four `FirstStep.js` files contains ~500 to ~880 lines with duplicated JSX for upload boxes and file lists.

## Proposed Changes
1. **`<DocumentSourceCards />`**:
   - Centralizes the 4 or 5 upload options (Local file dropzone, Google Drive, Dropbox, OneDrive, and DMS if enabled).
   - Configurable props: `onDrop`, `onDropboxSelect`, `onGoogleDriveSelect`, `onOneDriveSelect`, `onDmsSelect`, `isDmsEnabled`, `disabled`.
   - Uses unified design tokens and responsive grid layout.
2. **`<UploadedDocumentsTable />`**:
   - Renders the structured list of uploaded primary documents with page count badges, status, delete modal triggers, and actions.
   - Configurable for multi-document flows (`Upload Flow`, `Templates`) and single/bulk document flows (`BulkSend`, `SelfSignature`).
3. **Integration**:
   - Refactor `Upload Flow/Step1/FirstStep.js`, `BulkSend/Step1/FirstStep.js`, `SelfSignature/Step1/FirstStep.js`, and `Templates/Step1/FirstStep.js` to utilize `<DocumentSourceCards />` and `<UploadedDocumentsTable />`.
   - Keep all service calls (`uploadFlowService`, local state, routing) intact without changing any API request payloads or response handlers.

## Verification
- Test all 4 Step 1 views to ensure dropzone, cloud buttons, and document tables render cleanly.
- Verify `npm run build` succeeds with zero errors.
